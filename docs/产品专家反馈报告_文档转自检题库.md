# 「文档一键转智能自检翻卡题库」产品反馈报告

> 评审视角：资深产品专家（C 端工具 / AI 应用方向）
> 评审基准：线上版本 question-self-check.app.workbuddy.host（2026-10-09），含四轮外部评审迭代后的状态
> 标注约定：🟢 = 已上线且运转良好（报告仅指出待加强处）；🟡 = 部分实现，有明确缺口；🔴 = 缺失，需立项

---

## ① 定位与价值

**1.1 目标用户画像在产品内不可见 🟡**
- 问题：落地页写了"适合考研 / 考证 / 期末复习 / 笔记自测"，但四类用户的核心诉求不同——考研党要"真题+高频考点权重"，考证党要"按章节刷+通过率"，大学生要"考前突击"，自学者要"间隔重复防遗忘"。产品目前对所有用户提供完全相同的流程，没有任何画像分流。
- 影响：中。不阻断使用，但"为什么选你而不是 Anki / Quizlet"无法回答，留存天花板受限。
- 建议：短期在导入页加一个"使用目的"轻选择（考前突击 / 日常巩固 / 只练错题），据此调整默认抽题密度和总结页话术；长期把"只练不熟悉"升级为复习计划入口。

**1.2 "AI 生成题库"与"原文提取"的预期区分已做，但可再前置 🟢**
- 问题：登录页与步骤 2 已分别说明"规则+大模型双引擎"和各自边界，LLM 模式切换还有外发确认弹窗——这块做得比多数同类产品诚实。缺口在于：用户在**上传前**看不到"我的文档会被怎么处理"的一句话说明，要翻到第二步才恍然。
- 影响：低-中。涉及首次信任建立。
- 建议：把"本地规则免上传 / LLM 会发送文本"的一行对比，前置到步骤 1 上传区（一行小字即可，不必弹窗）。

**1.3 隐私卖点前置不足 🟡**
- 问题：隐私说明做得扎实（大白话弹窗、不用于训练、可换自有模型），但藏在协议链接和特性卡第 4 条里。对"上传个人笔记"类产品，隐私是**转化要素**不是合规附属品。
- 影响：中。
- 建议：登录表单上方加一行可展开的"🔒 你的数据怎么处理？"速览（3 行内），点击展开详情弹窗。

## ② 登录与首屏体验

**2.1 游客 Demo 已上线，但"示例数据"与游客路径未打通 🟡**
- 问题：游客模式（免注册一键进入）与内置示例文档（✨ 加载示例）都已存在，但两者没有串联——游客进来看到的仍是空工作区，需要自己发现示例按钮。理想动线是：点游客 → 自动载入示例 → 10 秒内翻到第一张卡。
- 影响：高（首访激活率）。工具产品的"啊哈时刻"必须压缩到 30 秒内。
- 建议：游客登录成功后自动执行 loadDemo 逻辑并 toast 引导"已为你准备了一份示例，直接点下一步体验"。

**2.2 能力边界与风险提示 🟢**
- 已覆盖：LLM 外发确认、幻觉提示条、扫描件识别有限声明、大文件分片说明。无需大改。
- 微调建议：抽题完成后若无"0 题"但也少于 3 题，补一句"可能因格式问题漏识别，试试 AI 净化或 LLM 模式"——中等结果目前没有引导。

**2.3 登录方式布局 🟡**
- 问题：手机号+微信+支付宝三选一已够用（第三方图标重复块已删）。真实缺口是**无兜底**：短信通道故障时用户被锁死，且游客数据无法"升级"为正式账号（游客做了 50 题，注册后全丢）。
- 影响：中-高（游客转化路径断裂是硬伤）。
- 建议：①游客会话内提供"保存我的进度 → 绑定手机号"按钮，注册后把 guest 用户数据迁移到正式账号（后端一次 UPDATE 即可）；②短信失败时提示"验证码收不到？可联系管理员开启邮箱登录（规划中）"。

## ③ 核心业务链路缺陷

**3.1 导入解析：格式容错已达中上，缺"半结构化"兜底 🟡**
- 问题：PDF/Word/TXT/MD/图片/拍照/粘贴全支持，脏数据过滤（闲聊/日程/励志）已验证有效。缺口：**选项藏在题干里的题目**（如 "1. 下列哪项正确？A.xx B.xx" 挤在一行）本地规则识别不稳；表格跨页/合并单元格解析未验证。
- 影响：中。影响的是"格式最随意的真实用户文档"这一最大群体。
- 建议：本地规则加"行内选项拆分"（正则切 A. B. C. D.）；解析后若单题题干超过 300 字且含 ≥3 个 "字母." 模式，自动提示用户"疑似选项未拆分，试试 AI 净化"。

**3.2 卡片人工编辑 🟢（本轮新上线，需观察）**
- 已有：单题编辑题干/答案、单题删除、一键去重、手动添加、题型指定、重新生成答案。
- 缺口：无**批量勾选删除**；编辑无撤销；去重只对比题干精确匹配（改一个标点就漏）。
- 建议：题库列表加多选模式；去重升级为相似度（编辑距离 ≤ 5 或 bigram ≥ 0.85）并支持预览对比。

**3.3 翻卡交互与快捷键 🟢**
- 已有：空格/F/U 快捷键、上一题回改、随机/顺序、原文对照、错题本、语音输入。
- 缺口：快捷键只在卡片下方一行小字，可发现性差；客观题"点了选项但直接看答案"与"看了答案没标记"的结果边界对用户不透明（未标记按跳过统计，但用户不知道）。
- 建议：快捷键 hover 提示（? 键呼出快捷键面板）；作答面板加一行实时状态"本轮已标记 X / 跳过 Y"。

**3.4 复习机制与间隔重复 🔴（最大的产品级缺口）**
- 问题：目前只有"一轮自检 + 只练不熟悉"。没有 SRS（间隔重复）：熟悉/不熟悉是**静态标签**，不是调度依据。Anki 类产品的核心价值"该忘的时候正好出现"完全缺失。
- 影响：高。这决定产品是"一次性考前工具"还是"长期学习伙伴"——直接影响复访率。
- 建议：分两步走。①低成本版：给每题加 next_review 字段，熟悉 +3 天、不熟悉 +当天，历史会话里出"今日待复习"入口（一张表即可，无需复杂算法）；②再迭代 SM-2 类算法。切忌一步到位做完整 Anki 克隆。

**3.5 数据导出与题库管理 🟡**
- 已有：薄弱项复制清单、文档/会话两级历史、删除。
- 缺口：无**文件级导出**（Markdown/CSV/Anki 可导入格式）；题库无重命名；多套题库无标签/搜索；历史会话无"基于上次错题再练一轮"。
- 影响：中。导出是用户"把价值带走"的凭证，也是传播触点（导出的 md 带 footer 即免费获客）。
- 建议：先加 Markdown 导出（格式最简单、通用性最强，文件名带 `# 来自问题自检`）；题库重命名与搜索紧随其后。

**3.6 统计 🟢**
- 已有：掌握率（口径已注明）、方面级统计、得分率、中途结束说明。
- 缺口：无跨会话趋势（每次自检是孤岛）。建议在历史记录顶部加"近 7 次掌握率"迷你折线（后端数据已齐，纯前端绘制）。

## ④ AI 能力边界与风险

**4.1 编造内容核验 🟢（领先同类）**
- 已有：AI 幻觉常驻提示、"原文对照"一键定位出处片段（bigram 相似度）、重新生成答案、答案 0 误差节点裁剪（经 8 章陷阱文档实测 59 题零幻觉）。
- 增强：原文对照目前只在翻卡页，题库列表页也该有（编辑前核对场景）。

**4.2 本地解析隐私边界 🟢**
- 已有：LLM 外发确认弹窗（记住选择）、隐私大白话、可换自有模型。
- 残余风险：用户"记住选择"后长期不再被提醒。建议：每 30 天或换文档类型时重提醒一次（一行代码成本）。

**4.3 长文档分片策略 🟡**
- 问题：8MB 分片上传 + 最小节点分批 + 异步任务 + 15 分钟上限，工程上稳。但用户侧**不可见**：不知道进度到哪一步、哪个版块失败了、失败后怎么重试单个版块。
- 影响：中（大文档用户的心智黑盒）。
- 建议：任务列表已按文件显示进度，补两点——版块级失败明细露出（后端 `failed` 数组现成）+ "仅重试失败版块"按钮。

**4.4 模型与成本控制 🔴（对外暴露层面）**
- 问题：内置服务端 Key 免费供所有用户调用 LLM，无任何额度/限流。恶意脚本可在数小时内刷穿账单。
- 影响：高（商业化前必须解决）。
- 建议：立即做——按 token 的用户级日额度（如 20 次抽题/天）+ 登录用户才能用 LLM 模式（游客仅本地规则）+ IP 限频。上线前无需告知用户"无限免费"，反过来做"免费额度 + 邀请解锁"反而是运营抓手。

## ⑤ 商业化与长期路线

**5.1 额度公示 🟡**
- 问题：写了"免费"但没写边界。用户预期管理差，将来任何收费动作都会被视为背刺。
- 建议：落地页加一行"公测期全功能免费"；一旦引入额度，同一位置改为额度表。

**5.2 两条路线的选择（核心战略判断）**

| | 路线 A：轻量工具 | 路线 B：深度学习平台 |
|---|---|---|
| 定位 | "文档→题库→自测"一次性完成，用完即走 | Anki 式长期学习伙伴，SRS+统计+社区 |
| 优势 | 开发成本低、获客简单、天然匹配"考生突击"场景 | 留存高、付费意愿强（Anki iOS 卖 25 美元） |
| 劣势 | 无复访、难收费 | 开发周期长、教育用户成本高 |
| 判断 | **当前阶段选 A，用 A 的用户量验证 B 的需求** | SRS（3.4）是切向 B 的第一块砖 |

- 建议节奏：3 个月内打磨 A（导出、编辑、额度、移动端）→ 上线 SRS 最小版试水"复习"心智 → 数据好再投入路线 B。

**5.3 移动端适配 🟡**
- 已有：560px 断点（触控尺寸、防 iOS 缩放、两列卡片）。
- 缺口：翻卡核心场景（睡前刷题）未做专项——卡片高度未按视口适配、快捷键在移动端无替代（滑动标记）、语音输入在移动端权限路径未验证。
- 建议：`@media (pointer:coarse)` 下把 F/U 键替换为左右滑动标记；卡片高度 `calc(100vh - 工具栏)`；这是路线 A 的最后一公里。

## 总结

这个产品的**抽题内核已经过硬**——经过四轮外部评审与 8 类陷阱文档实测，幻觉控制、表格/代码/数字精度、脏数据过滤都达到了同类中上水平，交互闭环（编辑/回改/原文对照/去重/导出）也已补齐。当前真正的战略级缺口只有三个：**复习机制（SRS）缺失决定它还是"工具"而非"伙伴"；LLM 额度裸奔是商业化前必须拆的雷；游客→注册的进度迁移断裂浪费了最大的转化资产**。P0 两项一周内可落地，SRS 最小版两周——做完这三件事，产品就从"演示项目"跨入"可运营产品"。
